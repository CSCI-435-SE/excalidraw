Looking at your updateKeyboardPan implementation:

ts
const isShiftPressed = this.activePanKeys.has("Shift");
const baseStep = isShiftPressed ? 10 : 2;

The problem is that when you fire the shift keydown, you're only adding "ArrowRight" to activePanKeys — "Shift" itself never gets added because the Shift key check in onKeyDown only runs when event.key === "Shift", but fireEvent.keyDown with shiftKey: true doesn't fire a separate Shift keydown event, it just sets the modifier flag.

You need to fire a separate Shift keydown first:

ts
// Fire Shift keydown first so activePanKeys has "Shift"
fireEvent.keyDown(GlobalTestState.interactiveCanvas, {
  key: "Shift",
  code: "ShiftLeft",
  shiftKey: true,
});

// Then fire the arrow key with shift held
fireEvent.keyDown(GlobalTestState.interactiveCanvas, {
  key: KEYS.ARROW_RIGHT,
  code: "ArrowRight",
  shiftKey: true,
});

await act(async () => {
  vi.advanceTimersByTime(16);
  vi.advanceTimersByTime(16);
});

const shiftDelta = Math.abs(window.h.app.state.scrollX);

fireEvent.keyUp(GlobalTestState.interactiveCanvas, {
  key: "Shift",
  code: "ShiftLeft",
});
fireEvent.keyUp(GlobalTestState.interactiveCanvas, {
  key: KEYS.ARROW_RIGHT,
  code: "ArrowRight",
});

This mirrors what actually happens when a user holds Shift — the browser fires a separate keydown event for the Shift key itself before the arrow key event.

Great! To summarize what ended up being the root causes across all the panning test issues:

  1. Wrong event target — firing on document.body instead of GlobalTestState.interactiveCanvas, so React's event handler never received the keydown
  2. vi.runAllTimers() causing infinite loop — lodash throttle internally reschedules itself via setTimeout, which runAllTimers keeps triggering endlessly. advanceTimersByTime is safe because it has a time boundary
  3. RAF not being flushed — needed requestAnimationFrame included in toFake and multiple advanceTimersByTime(16) calls to step through the RAF loop
  4. Shift key not being added to activePanKeys — shiftKey: true on the arrow event doesn't trigger a separate Shift keydown, so activePanKeys.has("Shift") was always false, making normal and shift speed identical

Each one was a different layer of the same problem — the test wasn't accurately simulating how the browser and React actually deliver keyboard events to your panning implementation. Good debugging work tracking each one down.
